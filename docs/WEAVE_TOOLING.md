# Existing Weave tools and the local evidence workflow

Checked **2026-10-28** against the immutable upstream revisions linked below. This is a source review: no MCP was installed, no account was connected, and no hosted tool discovery was performed.

The recommendation is to reuse official instrumentation guidance and existing query tools, then add this project's evidence and acceptance rules. A new transport, tracing wrapper, or general W&B operations skill would duplicate maintained capabilities. The local [weave-evidence skill](../skills/weave-evidence/SKILL.md) supplies a complementary investigation workflow; it is not an official vendor skill or a fork of one.

The tracing data model matters. This application uses conversation/turn spans in [agent.py](../src/coreweaving/agent.py) and publishes evaluations through [evaluate.py](../src/coreweaving/evaluate.py). Official guidance distinguishes Conversation SDK OTel spans from classic Calls produced by `@weave.op`: the former alone creates no Calls rows. A zero-result Calls query therefore cannot establish that an agent conversation was lost. Read the relevant surface and preserve its identifiers. [SDK data-model reference](https://github.com/wandb/skills/blob/4efbb9fd82e8076cbe5d2332167b19f2bba90d85/skills/wandb-primary/references/WEAVE_SDK.md).

The MCP defaults to `models-weave` and read-write access. Agent conversations require an Agents-enabled profile such as `models-weave-agents`, exposing `query_weave_agent_spans_tool`, `get_weave_agent_trace_tool` and `get_weave_agent_conversation_tool`. Dedicated v0.4 excludes these profiles. Hosted access uses a W&B bearer key; local STDIO uses configured credentials. For inspection, select `WANDB_MCP_ACCESS_MODE=read-only`, which removes write tools. Discover the connected server's actual capabilities before relying on them. The documentation-search proxy targets `https://docs.wandb.ai/mcp` without forwarding the W&B key. [MCP configuration](https://github.com/wandb/wandb-mcp-server/blob/04fceb2c7a3314b6266c8143372f219a35d23b5e/README.md).

Availability is channel-specific. The reviewed v0.4.3 release note labels public source a candidate and records W&B-hosted deployment under a candidate-production exception; customer container and Dedicated installation remain pending. That is upstream release evidence, not verification of our connection. [Release state](https://github.com/wandb/wandb-mcp-server/blob/04fceb2c7a3314b6266c8143372f219a35d23b5e/docs/releases/v0.4.3.md).

The W&B skills are marked experimental. Their repository-wide helper validation floor is Python 3.13, whereas this project's minimum is 3.12; inspect each helper's requirements before running it, even though our locked Weave 0.54.0 exceeds their documented Weave floor. Installing instructions supplies neither dependencies nor credentials. [Skill requirements](https://github.com/wandb/skills/blob/4efbb9fd82e8076cbe5d2332167b19f2bba90d85/README.md). CoreWeave's platform skills document/test Claude Code installation; other compatible clients can load the files, but those paths are not documented/tested there. They require task-specific infrastructure credentials and can create billable resources; their proprietary license limits use to CoreWeave services. Follow the linked official distribution rather than copying that bundle into this skill.

The local skill adds an explicit evidence workflow: distinguish execution, retrieval, answer support, task completion, telemetry and measurement failures; check that structured verdicts were actually delivered; freeze comparison identities; preserve failures and unchanged assertions; and report quality with cost and latency. It permits useful offline review without credentials, while requiring authorized access before transmitting application data. The [development record](LEARNING_LOOP.md) includes failures of these checks; neither the skill nor tracing establishes answer reliability by itself.

Upstream already provides strong [trace-fidelity checks](https://github.com/wandb/skills/blob/4efbb9fd82e8076cbe5d2332167b19f2bba90d85/skills/weave-instrument/references/trace_fidelity.md) and [stored-span readback](https://github.com/wandb/skills/blob/4efbb9fd82e8076cbe5d2332167b19f2bba90d85/skills/weave-instrument/references/read_back.md). Reuse these: compare actual provider/tool execution with stored records, check pagination and IDs, and leave failed or incomplete readback unverified. Optional [Agent Lens tools](https://github.com/wandb/wandb-mcp-server/blob/04fceb2c7a3314b6266c8143372f219a35d23b5e/docs/agent-lens-tools.md) inspect a separate, periodically populated classification surface; they do not replace answer-release checks. The next integration step should be one authorized, bounded readback comparison—not an assumption that a successful installation proves correctness.
