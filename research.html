Proposed experiment

Use a small set of predictable views: explanation, setup checklist, comparison, clarification and evidence gaps. Keep the composer, sources and cost receipt in stable places.

What adapts

A setup task becomes a checklist. A tradeoff becomes a table. You choose “Brief,” “Explain it,” or “Show evidence.” These are presentation choices around the same checked content; changing the view should not trigger another model call.

What stays dependable

The model chooses from validated modes; our renderers own the controls and layout. Invalid output falls back to ordinary text. Focus and keyboard order remain predictable. W3C guidance on context changes ↗

Earn adoption: users complete tasks with fewer corrections, while all citations and caveats survive. Test keyboard navigation, invalid layouts and display toggles. A prettier answer is not evidence of a more accurate answer.

Start with two handwritten renderers. No arbitrary model-generated JavaScript, extra layout classifier or replacement web framework is needed.

What would persuade us?

Routing: no regression on easy or unclear questions; a repeatable quality, cost or latency improvement on the relevant slice. Cap fan-out at two and enforce a shared budget.

Knowledge links: fix real prerequisite or compatibility misses without introducing unsupported claims. Count indexing work and added evidence tokens.

Voice and layout: fewer user corrections or easier task completion, with stable controls and exactly-once submission. Never sacrifice evidence visibility.

Method: freeze new source-annotated cases before tuning, repeat paired runs, inspect disagreements together and retain all failures. A small pilot is not universal proof.

What this research has—and has not—established

We inspected the working code and evaluation cases, consulted official documentation and primary research, and identified bounded experiments. We have not measured a benefit from specialist workers, a knowledge graph, voice or adaptive layouts. Published results concern different systems and workloads. The historical 12/13 submission evaluation and the six-case verification pilot above are separate measurements. Neither establishes a benefit from the proposed routing, graph, voice or layout changes.
