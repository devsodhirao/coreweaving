A documentation assistant that finds evidence, checks its answer, and leaves a record you can inspect. This guide connects the experience to the code behind it.

Four pieces, one conversation

The program runs on your computer. It calls Claude for language decisions and sends a record of those operations to Weave.

01 / INTERFACE
You askChat keeps your question and earlier turns together.
02 / AGENT
Claude choosesSearch, read, try a small example, or propose an answer.
03 / EVIDENCE
The program checksA separate model call compares the draft with source passages.
04 / WEAVE
You inspectSee tool calls, model usage, quality scores, and failures.

We control the tools, what they can access, the number of steps, and the rule that conversational answers must pass through verification. A separately labeled unchecked mode is reserved for experiments. Claude chooses its research steps within those boundaries.

The words, translated

API
A way for our program to ask another service to do something. An API key identifies the account paying for that access.
Agent loop
Ask the model what to do, run its chosen tool, return the result, and repeat until it can answer or reaches a limit.
Retrieval
Finding useful passages in the documentation. Our local keyword index ranks sections by their relevance to a search.
Context
The messages and evidence the model can see during a particular call.

Why keep it small?

A direct Python loop makes the important decisions visible: how tools run, how history is retained, and what happens when evidence is missing.

A local documentation snapshot makes searches fast and repeatable. Each saved page retains its original address, download time, and a fingerprint of its contents.

There is a tradeoff: keyword search can miss a paraphrase. The agent can try another query, and the evaluation includes questions that test this weakness.

Verification is another fallible check. We test whether it catches unsupported claims, and show uncertainty when the evidence is incomplete.

Three checks, at different times

CheckWhen it happensWhat we learn
Answer verificationBefore the user receives an answerDo sources support the claims? In coverage mode, did it address the requested parts and relevant prerequisites? Detected gaps return for revision.
Evaluation suiteDuring development, using a fixed set of casesWhich categories fail, and what needs investigation? The judge receives independently prepared reference evidence.

A useful test set

The original regression set has 13 cases. A separate six-case capability suite tests the new verifier policies:

  • Basic facts and setup instructions.
  • Questions that require several documentation pages.
  • Ambiguous requests where clarification helps.
  • Invented features that should be challenged.
  • Follow-ups that rely on earlier messages.
  • A small code example to execute and interpret.

Expected behavior and reference sources are written before evaluating the agent.

What a judge sees

The question, conversation, answer, reference passages, and explicit scoring rules.

It judges each case’s explicit assertions and rates correctness, completeness, source support and handling of uncertainty. Code checks confirm citation integrity and required execution. Verification adherence is a separate diagnostic, so an unchecked experiment can still produce a good answer.

A small test set can reveal concrete failures. It cannot establish a universal accuracy percentage. We also inspect sample judgments ourselves.

Your five-minute walkthrough

  1. Ask a multi-page question. Watch the search and reading steps.
  2. Ask a follow-up. Show that the agent keeps the relevant context.
  3. Challenge it with an invented feature. Explain how it handles missing evidence.
  4. Open the Weave conversation. Follow the model calls, tools, and verification.
  5. Show an evaluation failure. Explain the diagnosis, change, and remaining limitation.

Questions you should be able to answer

What makes this agentic?
The model chooses successive tools based on their results. The route through the docs can change for each question.
Why this retrieval approach?
It is inspectable, inexpensive, and suited to precise API names. We measure its weaknesses on paraphrased questions.
How did AI help?
Use the build log to show specific generated code, corrections, tests, and decisions you retained responsibility for.
What would more time buy?
Better retrieval for paraphrases, broader held-out evaluations, longer conversation tests, and operational hardening guided by observed failures.
