# Prospective retrieval questions

The [frozen probe](../../evals/retrieval-probe.json) contains 18 new questions across nine paired information needs. Each of the three categories has six questions: plain-language tasks omit the target API identifier, exact-API tasks supply it, and workflow tasks need complementary passages across pages. Topics include Op postprocessing, aggregate metrics, prompt versions, human review, version comparisons, bucket media, historical conversation imports, custom pricing and sub-agent context. These are prospective comparison questions, not an unexposed long-term holdout.

Questions and references were authored from the frozen document inventory, outlines and exact `Corpus.read` text before viewing any comparison rankings. Authoring used no `Corpus.search`, embedding calls or model calls. Every reference quote was checked as an exact substring of its indexed passage. Alternative passages support the same nugget; they are not additional required reads. A single reference means one direct supporting passage was located, not that all alternatives were ruled out.

The current search interface returns at most two sections per page. Several questions need more than two distinct referenced sections from one page, so full curated nugget coverage is impossible in a single search under that cap. Keep the cap constant across arms and report achievable reference-coverage ceilings. This is a search-interface limit, not proof that a ranking algorithm missed a reachable result; the agent can read further sections after navigation.

Report exact reference recall with that limitation. Useful unlisted passages must not automatically be called irrelevant. Report results by information-need group as well as by query: the paired variants are correlated. Retrieval measurements do not establish answer correctness, and the curated references must not be supplied to the answer-generating agent.

Every question has two to four frozen answer assertions. The six possible paired live cases are selected by the JSON rule before rankings: two per category, skipping previously selected groups. This selects six distinct information needs. Retrieval results may determine whether to run that bounded comparison and which alternative to compare, but must not change its selected questions or assertions.

The references measure the snapshot's documented behavior, not execution against a current service. Source imperfections are retained: the custom-cost cookbook prose says `include_cost`, while its code and the API reference use `include_costs`; the probe uses the consistent documented code. The `add_cost` reference also contains unrelated annotation-queue argument prose, which is not used as evidence. No requirements depend on those stray statements, undocumented guarantees, or copying source examples verbatim.
