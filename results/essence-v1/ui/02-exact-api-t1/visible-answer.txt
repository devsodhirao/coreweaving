The difference is which version you get back. weave.ref("support_prompt:v3").get() loads version index v3, which is fixed. weave.ref("support_prompt").get() loads whatever version is currently :latest [S1]. Both short forms need weave.init(...). A fully qualified weave:/// URI doesn't [S1].

Key terms

A ref points to an object stored in Weave. Calling .get() fetches that object so your code can use it [S1].
Prompts are stored as versioned objects, so evaluations, experiments and production systems can point to the exact prompt version they ran with [S3]. Publishing a prompt with weave.publish creates a version that can't be changed [S1].

The two short forms

weave.ref(<name>) gets the :latest version. Every object has the :latest alias [S1, S2].
weave.ref(<name>:<alias_or_version>) gets a specific version. After the colon you can use an alias (like :production), a version hash or a version index (like v3) [S1, S2].
My inference: the result of support_prompt can change when you publish a new version, but support_prompt:v3 always gives the same version. Use the pinned form when you need results you can reproduce.

Do you need weave.init? Yes, for both short forms [S1]. A short ref like support_prompt doesn't say which team or project it belongs to, and weave.init supplies that.

import weave

weave.init("your-team-name/your-project-name")
pinned = weave.ref("support_prompt:v3").get()
latest = weave.ref("support_prompt").get()

Fully qualified URI Yes, it changes the requirement: weave.ref(<fully_qualified_ref_uri>) doesn't need weave.init(...) [S1]. The URI names the team, project, object and version itself [S2]:

import weave

prompt = weave.ref(
    "weave:///your-team-name/your-project-name/object/support_prompt:v3"
).get()

The version part of the URI works the same way as above: it can be a hash, an index like v3 or an alias like :latest [S2].
