They form one loop. Tracing records what your app or agent actually does. Evaluations measure quality against fixed test cases before you ship. Signals score live agent traffic automatically, so problems in production show up. Weave describes itself as an observability and evaluation platform that helps you understand what your AI application is doing, measure how well it performs, and improve it over time [S5].

Tracing (the foundation): Traces capture each operation's inputs, outputs and structure as a Call (one recorded function or LLM call). They help you debug, evaluate and monitor LLM-powered code [S7]. There are two paths. Agent integrations capture sessions, turns, LLM calls and tool calls in the Agents view. LLM-application integrations capture individual Calls in the Traces view [S3].
Evaluations (testing before release): An Evaluation object combines a dataset of examples with one or more scoring functions (scorers, which grade outputs). You run it against a model or function, and each run measures performance [S2]. This lets you track which model and prompt versions produced which results, compare evaluations across metrics, and spot regressions [S2, S6].
Signals (monitoring in production): In the Agents view, the Signals tab shows tags and ratings for your agent's conversations. Signals can score response quality, notice when a user is frustrated, or flag NSFW content, and they point you to the traces that need attention [S1]. A rating is a number from 0.0 to 1.0; a tag is a label such as "user-frustration". Both are applied to matching spans (parts of a trace), and a turn is one exchange between the user and the agent [S4].

How they connect (my inference from the docs): traced agent conversations are what Signals score. The traces that Signals flag show where quality is slipping, which can guide new test cases and re-running evaluations as you change prompts or models. Weave also says you can score production traffic with the same scorers you use in evaluation [S9].
