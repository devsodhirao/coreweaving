In short, tracing records what your application or agent does. Evaluations test it against a fixed set of examples so you can compare versions. Signals score real agent conversations in production. Each one answers a different question.

Tracing (records what happens): There are two ways to trace. Agent integrations capture sessions, turns, LLM calls and tool calls from multi-turn agents, and show them in the Agents view. LLM-application integrations record individual LLM calls and pipeline steps as Weave Calls in the Traces view [S3].
Evaluations (offline testing): An Evaluation object brings together a dataset of test examples and one or more scoring functions (scorers). You run it against a model or function. Each .evaluate() call creates an evaluation run, which you can compare with other runs to spot regressions. Think of the Evaluation as a blueprint and each run as one measurement [S2].
Signals (production monitoring for agents): The Signals tab in the Agents view shows tags and ratings on your agent's conversations. Tags are labels like "user-frustration" or "nsfw". Ratings are numeric scores from 0.0 to 1.0. Both are assigned to matching spans. A turn is one exchange between the user and the agent [S4]. Signals can automatically score response quality, notice when a user is frustrated, or flag NSFW content. They point you to the traces that need attention [S1].

How they fit together (my inference from the docs):

Trace your agent first. Signals work on the conversations shown in the Agents view, and agent tracing is what puts them there [S1, S3].
Before shipping changes, run evaluations to measure them against fixed test examples and catch regressions [S2].
Once the agent is in production, use Signals to catch quality and safety problems, then open the flagged traces to see what went wrong [S1].
