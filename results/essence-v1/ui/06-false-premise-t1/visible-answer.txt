I can't give you an exact call for weave.enable_hallucination_free_mode(). I couldn't find that function in the Weave docs I searched, and nothing I read promises an agent will never hallucinate. Writing that call would mean inventing an API.

What the docs do describe are scorers: checks that look at your app's output and flag possible hallucinations after it's been generated. They help you measure and catch problems, but they don't stop the model from hallucinating.

HallucinationFreeScorer (built in): checks whether your AI system's output includes hallucinations based on the input data. You can change its system_prompt and user_prompt to define what "hallucination" means for you. Its score method expects an input column named context, and you can use column_map if your data uses a different name. In the documented example it runs inside a weave.Evaluation and reports has_hallucination counts [S1].
WeaveHallucinationScorerV1 (local scorer, Python SDK only): a small model that runs on your machine and returns a result with a passed flag and metadata [S2].
import weave
from weave.scorers import WeaveHallucinationScorerV1

hallucination_scorer = WeaveHallucinationScorerV1()

result = hallucination_scorer.score(
    query="[USER_QUERY]",
    context="[RETRIEVED_CONTEXT]",
    output="[AGENT_OUTPUT]",
)
print(f"Output is hallucinated: {not result.passed}")

This follows the documented example [S2]. You could check result.passed at runtime and return a fallback answer when it's False. That's my suggestion, not a documented feature. It lowers the risk of hallucinations but doesn't eliminate them, because the scorer itself can be wrong.
