# Shorter audit reports, unchanged responsibility

Status: applied only after all twelve writer diagnostic attempts were preserved. The final diagnostic attempt hit its reserved-spend allocation, so the model comparison is inconclusive. The writer remains Opus provisionally; this is a separate reporting repair, not a model-ranking result.

The simplified loop still took 74.28 seconds (Sonnet writer) and 96.24 seconds (Opus writer) on the first overview. Both used three verification calls. Each auditor response emitted about 1,700–2,300 tokens and took roughly 14–19 seconds. Removing control-flow machinery alone did not remove this work.

Source inspection distinguishes useful findings from overreach. Asking the writer to read the Add-to-dataset procedure before asserting it, and correcting “evaluations score an Evaluation object,” are useful checks. Requiring every legacy monitoring variant or a general Ops survey to explain a scoped agent overview adds an unrequested obligation. Supported recommendations connecting observed failures to repeatable tests do not require a documented automatic integration.

Proposed correction after the comparison:

- Keep the original question/history, read evidence, all material factual/code checks, explicit missing parts, deterministic citations and syntax checks.
- Ask the auditor to report only three fields: passed, blocking issues and missing requested parts. Issues identify unsupported/partial claims or code defects. A clean audit has no findings. Enumerating positive claims is not proof they were checked correctly, and it consumes output/time.
- Accept a supported, scoped explanation without surveying unrelated variants. Request an unread passage only for an actual claim or an unmet requested part. A recommendation must not imply an undocumented built-in integration or guarantee.
- Preserve bounded ordinary repair and explicit verified partials; add no new runtime path.

Validate the changed report with positive synthesis/composition and negative invented-API, requested-omission and misleading-partial controls, then the unchanged full regression and actual browser tasks. Compare measured usefulness and time, not just output size. Any writer diagnostic remains attributed to its earlier source; it cannot prove a speed effect for this audit change.

A concrete second failure justified removing the positive-claim record contract: in `ops-t1-claude-opus-5-5.json`, corrected drafts 2/3 had all claims labeled supported and no missing parts, but quote-anchor bookkeeping rejected the auditor’s code summary and the app returned no answer. This repair removes that category of report-format failure; it does not establish semantic accuracy. Verification contract is now 6.
