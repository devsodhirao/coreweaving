What the docs do describe is detection and intervention:

HallucinationFreeScorer checks whether your AI system's output includes hallucinations based on the input data [S1]. You create it with from weave.scorers import HallucinationFreeScorer and scorer = HallucinationFreeScorer() [S1]. You can customize its system_prompt and user_prompt to define what "hallucination" means for you [S1]. Its score method expects an input column named context, which you can map with column_map [S1].
Evaluation: you can pass the scorer to weave.Evaluation(dataset=..., scorers=[hallucination_scorer]). The docs example reports a has_hallucination result [S1]. This measures hallucinations. It doesn't prevent them.
Guardrails: these use inline Weave Scorers to assess user input or LLM output and adjust the LLM's responses in real time [S2]. They require code changes because they affect your application's control flow [S2]. The guardrails page says they can block or modify responses when scores exceed thresholds [S2].

A scorer or guardrail is a check on outputs. The pages I read don't claim it eliminates hallucinations. I read the HallucinationFreeScorer and guardrails overview sections. I didn't read every page in the docs.
