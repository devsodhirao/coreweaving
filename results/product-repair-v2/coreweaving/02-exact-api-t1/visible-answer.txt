Short answer: weave.ref("support_prompt:v3").get() loads a specific version (v3), while weave.ref("support_prompt").get() loads the :latest version. Both need weave.init(...) first. A fully qualified weave:/// URI is the exception.

Pinned version: weave.ref(<name>:<alias_or_version>) retrieves a prompt by alias, version hash, or version index [S1]. support_prompt:v3 therefore targets version 3. Published versions are immutable [S1], so this ref points at the same version each time.
Name only: weave.ref(<name>) retrieves the :latest version [S1]. What it returns can change when a newer version becomes latest. That follows from "latest", but the page doesn't state it in so many words.
weave.init: Both short forms "require calling weave.init(...)" [S1]. The docs' example calls weave.init("your-team-name/your-project-name") before weave.ref("support_prompt:v3").get() [S1].
Fully qualified URI: weave.ref(<fully_qualified_ref_uri>) retrieves the prompt at that URI and does not require calling weave.init(...) [S1]. This is the only form the docs say can skip it.
import weave

# Short forms: call weave.init first.
weave.init("your-team-name/your-project-name")
pinned = weave.ref("support_prompt:v3").get()
latest = weave.ref("support_prompt").get()

I read only this prompts page, so I can't say how the URI form behaves beyond that statement. I also haven't covered its exact URI format, which the page documents in a separate section.
