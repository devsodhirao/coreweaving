Evaluations measure quality against repeatable test cases [S3]. Signals score your agent's turns in production and point you to the traces that need attention [S1][S7].

Tracing: capturing what happened

Weave's tracing is built on Ops, Calls, Traces, and Threads [S2]. Each time an Op runs, Weave records a Call with its inputs, output, timing, parent/child links, and any errors [S6].
A Trace is the full tree of Calls that share one execution context [S4].

Evaluations: structured testing

An Evaluation object defines a dataset of test examples and one or more scoring functions. You run it against a model or function, and each .evaluate() call is one evaluation run [S3].
The goal is to measure performance on repeatable test cases, compare changes over time, and catch regressions (cases where a change makes things worse) [S3].

Signals: monitoring agents in production

In the Agents view, the Signals tab shows tags and ratings for your agent's conversations. Signals flag quality and safety issues, such as user frustration or NSFW content, and point you to the traces that need attention [S1].
To start scoring your agent's turns, you create signals. A turn is one exchange between the user and the agent [S5][S7].
Tags apply labels such as user-frustration to matching spans. Ratings give matching spans a score from 0 to 1 so you can measure improvement over time [S7].

How they fit together This is my interpretation of the cited pages. Tracing records the data that the other two build on [S6]. Evaluations score your application on curated, repeatable examples so you can compare versions [S3]. Signals score real agent conversations in production [S1][S7]. In practice: trace your app, use evaluations to measure changes, and use Signals to watch live behavior.
