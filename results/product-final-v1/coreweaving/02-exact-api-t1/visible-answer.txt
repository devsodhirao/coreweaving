The difference is which version you load. weave.ref("support_prompt:v3").get() always loads version v3. weave.ref("support_prompt").get() has no version, so it loads :latest. Both short forms need weave.init(...). A fully qualified weave:/// URI does not [S1][S2].

Pinned vs. latest

weave.ref(<name>:<alias_or_version>) gets a prompt by alias, version hash or version index, such as v3. Each published version is immutable, so a pinned ref always gives you the same content [S1].
weave.ref(<name>) gets the :latest version. The reference docs say the same thing: "If no version is provided, latest is used." Every object has the :latest alias, so what this returns changes when you publish a new version [S1][S2][S3].
.get() fetches the stored object. weave.ref(...) by itself only creates a reference to it [S1][S2].

Do you need weave.init? Yes, for both short forms. The reference docs say location can be a Weave ref URI, or name:version or name only "if weave.init() has been called." weave.init tells Weave which team and project to look in [S1][S2]:

import weave

weave.init("your-team-name/your-project-name")
pinned = weave.ref("support_prompt:v3").get()
latest = weave.ref("support_prompt").get()

Fully qualified URI Yes, it changes things. The URI already includes the team, project, object name and version, and the docs say this style "does not require calling weave.init(...)" [S1][S3]:

import weave

prompt = weave.ref(
    "weave:///your-team-name/your-project-name/object/support_prompt:v3"
).get()

You can also put :latest or another alias at the end of the URI instead of a version number [S3]. I haven't run these examples. They need the Weave SDK and access to your project.
