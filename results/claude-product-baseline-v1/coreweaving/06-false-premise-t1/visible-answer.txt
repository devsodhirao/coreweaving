What the docs do describe is detection and intervention:

HallucinationFreeScorer is a built-in scorer that checks whether your AI system's output includes hallucinations based on the input data [S1]. Its system_prompt and user_prompt can be customized, and its score method expects an input column named context [S1].
from weave.scorers import HallucinationFreeScorer

scorer = HallucinationFreeScorer()
WeaveHallucinationScorerV1 is a local scorer. It also checks whether output contains hallucinations based on the input data, and it uses the open source HHEM 2.1 model from Vectara [S3]. Local scorers return an object with a passed boolean [S3].
Evaluations: the built-in scorers page shows HallucinationFreeScorer used in a weave.Evaluation, and its example output reports a has_hallucination count [S1]. That measures hallucinations. It doesn't prevent them.
Guardrails use inline Weave Scorers to assess a user's input or an LLM's output and adjust responses in real time. They require code changes because they affect your application's control flow [S2]. They can block or modify responses when scores exceed thresholds [S2].

A scorer is a check, not a guarantee. The pages I read don't claim that a scorer or guardrail eliminates hallucinations. For production, the closest fit is a guardrail: run a hallucination scorer inline and block or alter flagged outputs [S2].
