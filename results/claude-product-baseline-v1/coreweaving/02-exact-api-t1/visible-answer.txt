weave.ref("support_prompt:v3").get() loads the specific version v3. weave.ref("support_prompt").get() loads the :latest version. Both need weave.init(...) first, because both are short-form refs. A fully qualified weave:/// URI is the case that doesn't need it.

Version difference

weave.ref(<name>) retrieves the :latest version of a prompt [S1]. The SDK reference says the same: if no version is given, latest is used [S3].
weave.ref(<name>:<alias_or_version>) retrieves a prompt by alias, version hash, or version index [S1]. v3 is a version index, so this call is pinned to that version.
weave.ref(...) only creates a reference to an existing object. .get() is what fetches the object [S1][S3].
All objects have the :latest alias [S2]. The docs I read don't say what "latest" resolves to over time, so I'm not describing it beyond that.

weave.init

Both short forms require calling weave.init(...) [S1]. The SDK reference agrees: name:version or name works only if weave.init() has been called [S3].
The docs' example calls weave.init("your-team-name/your-project-name") and then weave.ref("support_prompt:v3").get() [S1].

Fully qualified URI

Yes, it changes this. weave.ref(<fully_qualified_ref_uri>) retrieves the prompt at that URI and does not require weave.init(...) [S1].
The URI format is weave:///<your-team-name>/<your-project-name>/object/<object_name>:<object_version>. The version can be a hash, an index like v0, or an alias like :latest or :production [S2].
For example, weave:///your-team-name/your-project-name/object/support_prompt:v3 [S2]. This form carries the team, project and version, so you don't need to initialize a project first.
import weave

# Short form: needs weave.init first
weave.init("your-team-name/your-project-name")
pinned = weave.ref("support_prompt:v3").get()
latest = weave.ref("support_prompt").get()

# Fully qualified: documented as not requiring weave.init
prompt = weave.ref(
    "weave:///your-team-name/your-project-name/object/support_prompt:v3"
).get()
