In Weave, tracing records what your agent or app does. Evaluations test it against fixed test cases before you ship changes. Signals score the agent conversations you trace in production. Weave describes itself as an observability and evaluation platform that helps you see what your AI app is doing, measure how well it works and improve it over time [S3].

Tracing (seeing what happens): Weave shows you agent sessions and multi-turn conversations, or the individual function calls in your code [S6]. There are two ways to trace. Agent tracing is for agents, and those traces appear on the Agents page. Application instrumentation is for code built around separate calls, such as a RAG pipeline (an app that looks up documents before answering). These weave.op calls appear on the Traces page. You can use both in one project, but they create separate traces [S4].
Evaluations (testing before you ship): An Evaluation object combines a dataset of test examples with one or more scoring functions. You run it against a model or function, and each .evaluate() call creates an evaluation run [S2]. Use this to measure performance on repeatable test cases, compare changes over time and catch regressions (results that get worse after a change) [S2]. It also tracks which model and prompt versions produced which results [S8].
Signals (monitoring in production): Signals score agent turns. In the Agents view, the Signals tab shows tags and ratings for your agent's conversations. Signals can automatically score answer quality, notice when a user is frustrated or flag NSFW content. They point you to the traces that need attention [S1]. A turn is one exchange between the user and the agent. A rating is a score from 0.0 to 1.0, and a tag is a label such as "user-frustration". Both ratings and tags are assigned to matching spans, which are parts of a trace [S5]. To view them, select your project in Forge, then Agents, then the Signals tab [S7].

How they connect (my inference): You need agent tracing first, because Signals score the conversations shown in the Agents view. Signals then help you find problem conversations in live traffic. Evaluations check, in a controlled way, whether a fix actually helps, since they rerun the same test cases each time. Together this matches Weave's goals of visibility, systematic evaluation and production monitoring [S6].
