They're three layers of the same workflow. Tracing records what your app or agent actually did. Evaluations measure quality offline against a fixed set of test cases. Signals score live agent traffic automatically in production. 1. Tracing: the foundation Weave has two ways to trace. Agent integrations record sessions, turns, LLM calls and tool calls, and show them in the Agents view. LLM-application integrations record individual LLM calls and pipeline steps as Calls in the Traces view [S3]. The Weave SDK for Agents models agent → conversation → turn → LLM call → tool call. Each turn, LLM call and tool call sends an OpenTelemetry span, which is a structured record of one operation [S7]. The stated goal is to let you view, debug and evaluate your agent [S7]. 2. Evaluations: repeatable offline testing An Evaluation object combines a dataset of test examples with one or more scoring functions. You run it against a Model or a function. Each .evaluate() call produces an evaluation run [S2]. Use evaluations to compare changes over time and catch regressions (drops in quality) before you ship [S2]. 3. Signals: production monitoring on agent traces Signals live in the Signals tab of the Agents view. They tag and rate your agent's conversations to flag quality and safety problems and point you to the traces that need attention [S1, S6]. Tags are labels such as user-frustration. Ratings are scores from 0 to 1 attached to matching spans [S4, S8]. A turn is one exchange between the user and the agent [S4]. Scoring uses an LLM judge by default, or an HTTP endpoint you host [S1]. How they connect (my reading of the docs): Signals score spans from the Agents view, so you need agent tracing set up first [S1, S7, S8]. Use evaluations for controlled tests before release. Use Signals to keep watching quality on real traffic, where ratings help you measure improvement over time [S8].
