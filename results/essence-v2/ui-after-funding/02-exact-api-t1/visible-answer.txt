Short answer: weave.ref("support_prompt:v3").get() loads one specific version of the prompt (version index v3). weave.ref("support_prompt").get() has no version, so it loads the :latest version. Both short forms need weave.init(...). A fully qualified weave:/// URI does not [S1]. How they differ weave.ref(<name>) gets the :latest version of the prompt. weave.ref(<name>:<alias_or_version>) gets a version by alias, version hash or version index such as v3 [S1]. Every published version is immutable (it can't be changed later). So pinning :v3 lets evaluations, experiments and production use exactly the prompt version they ran with [S1, S3]. All objects have a :latest alias [S2]. My inference: the unpinned form can therefore return a different version after you publish a new one. A ref points to a stored object, and .get() fetches that object so your code can use it [S1]. Do you need weave.init? Yes for both short forms. They don't name a team or project, so you initialize the project first [S1]: Does a fully qualified URI change that? Yes. weave.ref(<fully_qualified_ref_uri>) does not require weave.init(...) [S1]. The URI includes the team and project, so it uniquely identifies the object [S2]: For example: weave:///your-team-name/your-project-name/object/support_prompt:v3. The <object_version> part can be a version hash, a version index like v3, or an alias like :latest or :production [S2].

```
import weave

weave.init("your-team-name/your-project-name")
prompt = weave.ref("support_prompt:v3").get()
```

```
weave:///<your-team-name>/<your-project-name>/object/<object_name>:<object_version>
```
