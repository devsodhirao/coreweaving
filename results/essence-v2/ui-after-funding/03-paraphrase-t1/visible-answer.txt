Pass postprocessing functions to the @weave.op decorator. Weave runs them on the data it logs, so you don't have to change the function body [S1].

postprocess_inputs: receives a dict that maps argument names to argument values. It returns a dict with the transformed inputs to record, so you can drop or mask a field like a password [S1].
postprocess_output: receives whatever the function would normally return and returns a transformed version to record, for example a copy with the secret field replaced by "REDACTED" [S1].
The docs present this as a way to change "the data that Weave logs without modifying the original function," with hiding sensitive data as the example [S1]. In the docs' example, the function still receives the real password and puts it in its return value [S1]. My inference is that only the recorded copy is redacted, and your code still gets the real values.
This is a Python feature. The docs say it isn't available in TypeScript yet [S1].

This follows the documented example [S1]. Call weave.init(...) before calling the op. Without it, a decorated function runs normally but Weave doesn't track it [S1].
