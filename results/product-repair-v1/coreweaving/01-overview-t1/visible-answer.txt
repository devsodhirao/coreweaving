Tracing captures what your agent or application does. Signals attach tags and ratings to the agent activity that tracing captures. Evaluations are a separate, dataset-based way to measure an application. The docs I read describe each piece but do not give one combined statement of how all three fit, so the relationships below are my reading of them.

Tracing is the record.

With the Weave SDK for agents, every turn, LLM call, and tool call emits an OpenTelemetry span, which is a structured record of one operation [S8].
Traces appear in the Agents tab. Each conversation shows a multi-turn timeline with nested tool calls, token usage, and feedback [S8].

Signals are scoring on top of that agent activity.

In the Agents view, the Signals tab shows tags and ratings for your agent's conversations [S1].
A rating is a number from 0.0 to 1.0 assigned to a matching span. Tags are labels on matching spans, such as "user-frustration" or "nsfw" [S4].
Signals surface quality and safety issues, find patterns, and highlight the traces that need attention [S1].
Because the Signals tab sits in the Agents view and its tags and ratings attach to spans, tracing is what produces the spans that Signals label. This is an inference. I did not find a sentence that says so directly.

Evaluations are the structured test.

An Evaluation combines a dataset of test examples with one or more scoring functions. You run it against a Model or a function that holds your application logic [S3].
Each .evaluate() call is an evaluation run. The aim is to measure behavior against repeatable examples, compare changes over time, and identify regressions [S3].

How they relate

Tracing makes the activity visible.
Evaluations check a version of your application against curated examples you chose.
Signals score and tag the agent conversations that were actually traced, so you can see where to look.
Evaluations and Signals both score outputs, but they work on different inputs.
