Short answer: weave.ref("support_prompt:v3").get() loads a specific version (v3), while weave.ref("support_prompt").get() loads the :latest version. Both need weave.init(...) first. A fully qualified weave:/// URI is the case that doesn't need it.

Pinned vs. unpinned: weave.ref(<name>) retrieves the :latest version of a prompt. weave.ref(<name>:<alias_or_version>) retrieves a prompt by alias, version hash, or version index [S1]. So support_prompt:v3 uses the version index v3, and support_prompt uses :latest. All objects have the :latest alias [S2]. Publishing a prompt with weave.publish creates an immutable version [S1].
weave.init: Both short forms require calling weave.init(...) [S1]. The docs' example calls weave.init("your-team-name/your-project-name") before weave.ref("support_prompt:v3").get() [S1].
Fully qualified URI: Yes, this changes the requirement. weave.ref(<fully_qualified_ref_uri>) retrieves the prompt at that URI and does not require weave.init(...) [S1]. The URI format is weave:///<your-team-name>/<your-project-name>/object/<object_name>:<object_version>. The version can be a hash, an index like v0, or an alias like :latest or :production [S2]. Here is an example URI: weave:///your-team-name/your-project-name/object/support_prompt:v3 [S2].

The URI carries the team, project, name, and version, so nothing else is needed to locate the object. That is my reading of the docs, not a statement they make.
